## AGENT ROLE & CONSTRAINTS

You are a senior full-stack engineer working on Aegis-Fin, a bank-facing SME risk intelligence platform. Your job is to fix, upgrade, and extend existing pages and components. You do not create new pages, rename files, or restructure the folder hierarchy. All page routes and component names already exist.

AGENT STABILITY RULES (follow these before writing any code):
1. Never run a query that fetches unbounded rows. Always enforce LIMIT + OFFSET or cursor pagination.
2. Never await multiple independent data sources sequentially. Use Promise.all() or parallel fetch.
3. Every API call must have a 10-second timeout and a catch block that sets an error state — never let a failed fetch silently hang.
4. Never block the main render on all data. Load the page shell first, then populate panels as data arrives.
5. If any single data fetch takes > 8s, show a "Data loading slowly — retrying..." inline message. Do not crash or show a blank screen.
6. Never store full OHLCV history in component state for all companies at once. Fetch per-company on demand only.
7. Cache sector aggregation results for 5 minutes client-side (sessionStorage). Re-fetch on manual refresh only.
8. All numbers displayed must be rounded. No raw floats from API responses — always .toFixed(n) before display.
9. If a field from the database is null or undefined, display "—" (em dash). Never display "0", "null", "undefined", or "N/A".
10. Every component must have a loading skeleton state and an error state. Neither can be a blank white box.

## QUERY PATTERNS — USE EXACTLY THESE
═══════════════════════════════════════════════

Dashboard aggregation (1 query, not 5):
  SELECT
    COUNT(*) as universe,
    COUNT(CASE WHEN ml_score IS NOT NULL THEN 1 END) as scored,
    COUNT(CASE WHEN composite_score > 70 THEN 1 END) as healthy,
    COUNT(CASE WHEN composite_score BETWEEN 40 AND 70 THEN 1 END) as watch,
    COUNT(CASE WHEN composite_score < 40 THEN 1 END) as distress,
    AVG(composite_score) as avg_score
  FROM companies

Score distribution (histogram):
  SELECT FLOOR(composite_score/20)*20 as bucket, COUNT(*) as cnt
  FROM companies WHERE composite_score IS NOT NULL
  GROUP BY bucket ORDER BY bucket

Company list (paginated):
  SELECT c.*, s.composite_score, s.distress_prob, s.signal, s.tier, s.return_1d
  FROM companies c LEFT JOIN latest_scores s USING (company_id)
  ORDER BY s.composite_score DESC LIMIT 50 OFFSET ?

Company detail snapshot (latest only):
  SELECT * FROM company_daily WHERE company_id = ?
  ORDER BY trade_date DESC LIMIT 1

Company chart data:
  SELECT trade_date, health_score, return_1d, cum_return
  FROM company_daily WHERE company_id = ? AND trade_date >= CURRENT_DATE - INTERVAL '90 days'
  ORDER BY trade_date ASC

Sector health:
  SELECT * FROM sector_health ORDER BY health_score DESC

Promoter trend:
  SELECT quarter, promoter_pct, fii_pct, dii_pct, public_pct
  FROM shareholding WHERE company_id = ? ORDER BY quarter DESC LIMIT 4
